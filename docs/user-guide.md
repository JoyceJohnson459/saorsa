# Saorsa 使用指南

Saorsa 是一个基于 OpenCode 的企业 AI 编程资源管理平台：管理员统一管理账户、项目组、模型与 API Key，实时查看各项目组和成员的调用量、Token、费用与风险；成员用自己的账户登录 OpenCode，选择计费项目组，用管理员分配的模型继续本地编程，**不需要也看不到任何真实 API Key**。

> 项目组只用于成员归属、模型授权、费用归集、预算与合规审计。Saorsa 不提供共享代码仓库、任务看板或多人协作功能；OpenCode 原有的本地文件、终端、Git 和 Agent 能力保持不变。

## 1. 角色与基本概念

| 概念 | 说明 |
|---|---|
| **管理员** | 唯一的管理角色。可以有多个管理员账户，权限完全相同，没有层级。 |
| **普通成员** | 默认账户类型。只能看到自己的数据、自己所属的项目组和被授权的模型。 |
| **项目组** | 费用归集与授权单位。一个成员可以属于多个项目组，但**每次调用只计入一个项目组**（当前计费项目组）。 |
| **供应商 / Key** | 上游模型服务（如 DeepSeek、Anthropic）及其 API Key。Key 只保存在服务端并加密，界面只显示遮罩。 |
| **模型别名** | 成员在 OpenCode 里看到的模型名称，例如 `saorsa/deepseek-chat`。 |
| **企业网关** | 所有受管模型请求都经过它：鉴权、项目授权、限流、预算、计费、风险检测。 |
| **受管调用** | 经过企业网关的调用。只有受管调用会被统计和审计。 |

## 2. 快速开始

### 管理员：从零到可用（约 10 分钟）

1. 打开 Saorsa 网址（例如 `https://saorsa.tech`）。首次访问会进入 **初始化 Saorsa** 页面，填写运维提供的一次性初始化令牌，创建第一个管理员。
2. **项目组 → 新建项目组**：填写项目编号、名称和**项目用途说明**。
3. **成员管理 → 新增成员**：选择所属项目组，系统生成一次性临时密码，通过安全渠道发给成员。
4. **模型与密钥 → 添加供应商**，再在供应商卡片里点 **添加 Key**，粘贴真实 API Key。
5. **添加模型**：填写上游模型 ID、别名和供应商官方单价。
6. 进入项目组详情，在 **模型授权** 里勾选模型并保存。
7. （建议）**预算与额度 → 新建预算**，给项目组设置月度额度。

### 成员：开始用 AI 编程（约 3 分钟）

1. 用管理员给的账户和临时密码登录 Saorsa 网页，按提示修改密码。
2. 在终端运行：
   ```bash
   opencode auth login https://saorsa.tech
   ```
3. 浏览器会打开授权页：选择计费项目组，阅读并确认使用告知，点 **授权此客户端**。
4. 回到终端，正常使用 OpenCode，选择 `saorsa/…` 或 `saorsa-anthropic/…` 开头的模型即可。

## 3. 管理员指南

### 3.1 登录与界面

- 管理员和成员使用同一个登录页。连续 5 次输错密码，账户会锁定 15 分钟（管理员可在成员详情里 **解除锁定**）。
- 左侧导航分为 **WORKSPACE**（总览、项目组、成员）、**GOVERNANCE**（模型与密钥、使用量与费用、风险审计、预算与额度）、**SYSTEM**（系统设置）以及 **PERSONAL**（管理员自己的个人页面）。
- 按 **⌘K / Ctrl+K** 可以快速搜索并跳转页面。
- 左下角 **GATEWAY STATUS** 显示网关、数据库、Redis 和供应商健康状态；点头像可以切换深色/浅色主题或退出登录。

### 3.2 总览工作台

- 顶部可切换 **今天 / 近 7 天 / 近 30 天**，指标卡的涨跌幅与“上一个同等时段”比较。
- **资源消耗趋势**：实线为当前周期费用，虚线为上个周期。
- **项目组费用分布**：各项目组费用占比。
- **项目组监控**：每个项目组的成员数、本时段费用和月预算使用率（≥80% 显示“预警”，≥100% 显示“超额”）。
- **实时网关事件**：最新的调用、风险和额度事件，可点 ⏸ 暂停。
- **导出报表**：下载当前时段的请求明细 CSV。

> 所有数字都来自网关的真实调用记录。费用标记“估算”的部分，表示供应商没有回传用量，需要和账单对账。

### 3.3 项目组

- **新建/编辑**：项目编号（2–32 位字母数字）、名称、用途说明、标签、并发上限、每分钟请求数和 Token 上限（留空表示使用企业默认值）。
- **项目用途说明很重要**：开启“项目相关性提示”后，系统会用它判断提示词是否与项目有关（只生成待复核提示，不会认定违规）。
- **成员**：添加或移出成员。移出后立即生效，该成员以这个项目组计费的 OpenCode 客户端将无法再发起新调用。
- **模型授权**：勾选该项目组可用的模型并保存，客户端约 1 分钟内同步。
- **归档**：归档后该项目组不能再产生新的调用，历史数据保留。

### 3.4 成员管理

| 操作 | 位置 | 说明 |
|---|---|---|
| 新增成员 | 成员管理 → 新增成员 | 可选“管理员”类型。临时密码只显示一次，成员首次登录必须修改。 |
| 批量导入 | 成员管理 → 批量导入 | 每行：`用户名,显示名称,邮箱(可选),项目编号(可选，多个用 \| 分隔)`，例如 `zhangsan,张三,zhangsan@example.com,VISION\|LEDGER` |
| 重置密码 | 成员详情 → 重置密码 | 生成新的临时密码，旧密码和所有会话立即失效。 |
| 强制下线 | 成员详情 → 强制下线 | 注销该成员的网页和 OpenCode 会话；也可只撤销某一个设备。 |
| 禁用 / 恢复 | 成员详情 | 禁用后无法登录，所有会话立即失效。 |
| 删除 | 成员详情 → 删除 | 软删除：账户无法登录并移出所有项目组，历史用量与审计记录保留。 |

成员详情页还能看到该成员近 30 天在各项目组的用量、常用模型、预算、请求时间线，以及每个设备当前使用的 **OpenCode 客户端版本**。

### 3.5 模型与密钥

**添加供应商**

- 协议选择：**OpenAI Chat 兼容**（OpenAI、DeepSeek、智谱、豆包/方舟、通义、Moonshot、OpenRouter 等）或 **Anthropic Messages**（Claude）。
- Base URL 示例：`https://api.deepseek.com/v1`、`https://api.anthropic.com/v1`。必须是 HTTPS，且主机在允许列表中（其他主机请运维加入 `SAORSA_UPSTREAM_HOST_ALLOWLIST`）。
- 可以为供应商设置 **并发上限** 和 **每分钟请求** 上限，用来保护上游账号的速率限制。

**管理 Key**

- **添加 Key**：粘贴后立即加密保存，之后任何人都看不到完整 Key（只显示后 4 位）。
- 同一供应商可以有多个 Key，按优先级使用；某个 Key 被上游拒绝或限流时会自动冷却并切换到下一个。
- **Key 独占分配（默认开启）**：每个 Key 同一时间只给一位成员使用，**有几个 Key 就能有几个人同时工作**，先选先得。例如添加 2 个 GLM、2 个 MiniMax、3 个 Kimi 的 Key，就能 7 人同时使用。Key 表格的 **占用成员** 列显示谁正在用、最近一次调用时间；成员下班忘记退出时可以用 **操作 → 释放占用** 收回（该成员会收到通知）。成员连续一段时间（默认 30 分钟）没有调用、退出 OpenCode 登录或被禁用时，Key 自动回到空闲。
- 管理员可在 **系统设置 → Key 分配方式** 改为“共享”（所有成员共用全部 Key，只受并发和频率上限约束）。
- **健康检查**：验证 Key 是否可用。
- **操作 → 轮换 Key / 停用 / 撤销并销毁**。撤销会永久销毁密文，无法恢复。

**模型与价格**

- 添加模型时填写上游模型 ID、别名（成员看到的名字）、上下文和输出上限、默认最大输出，以及**每百万 Token 的单价**（输入、输出、缓存读取、缓存写入）。请以供应商官方价格为准。
- **调价**：追加一个新的价格版本。每次请求按发生时生效的价格计费，调价不会改变历史报表。
- **并发 / RPM / TPM 上限**：可为单个模型设置全企业的并发、每分钟请求数和每分钟 Token 上限。

### 3.6 使用量与费用

- 按 **时间范围、项目组、成员、模型、供应商、状态、计费口径、风险** 任意组合筛选。
- **趋势**：按小时或按天查看费用与 Token。
- **分组汇总**：按项目组 / 成员 / 模型 / 供应商统计请求数、成功率、Token 与费用。
- **请求明细**：点击任意一行可查看请求 ID、OpenCode 会话、上游请求 ID、账本明细、上游重试记录和预算预留/结算。**默认不显示对话正文**。
- **对账调整**：在请求详情底部填写差额和依据（如供应商账单编号），系统会记录一条可审计的调整，不会修改原始计费记录。
- **导出 CSV**：请求明细，或按项目组 / 成员 / 模型汇总。

计费口径说明：**精确** = 供应商回传了用量；**估算** = 供应商没有回传（或流被中断），按内容长度估算；**待对账** = 进程中断等原因导致用量未知；**不计费** = 请求在调用上游前被拒绝。

### 3.7 预算与额度

- **新建预算**：范围可选 企业 / 项目组 / 成员 / 成员-项目 / 模型，周期可选 每日 / 每月 / 累计。
- **告警阈值**：默认 80%、95%，到达 100% 时也会提醒；管理员和相关成员会收到通知。
- **超额策略**：“超额拒绝”会在额度不足时拒绝新请求；“仅告警”只提醒不拦截。
- **单次请求上限**（可选）：防止单个超大请求花费过多。
- **临时提额**：只在当前周期有效，必须填写原因，会记入调整历史。
- **周期末预测**：按当前速度线性推算，仅供参考，不是账单。

> 系统在请求开始前按“最坏情况”预留额度，完成后按实际用量结算，所以并发请求也不会无限超支。额度快用完时，可能会拒绝实际花费很小的请求，这是有意的保护。

### 3.8 风险审计

- 顶部统计：**待人工复核**、**确定性规则命中**（如密钥泄露）、**AI 相关性标记**、**已复核**。
- 点击事件查看详情：检测规则、可解释依据（已脱敏）、关联请求、成员申诉记录。**查看详情本身会记入审计日志。**
- **人工复核**：选择 误报 / 确认 / 已处理 / 重新打开，并填写说明，成员会收到复核结果通知。
- 点右上角 **审计原则** 可以查看平台的审计边界。

风险类别：

| 类别 | 来源 | 能否阻断 |
|---|---|---|
| 敏感凭据泄露 | 确定性规则（API Key、私钥、带密码的连接串等） | 可设为直接阻断 |
| 疑似项目无关使用 | 关键词或审计模型（默认关闭） | 只能提示，不能阻断 |
| 资源滥用 / 费用异常 | 短时高频、费用突增 | 只能提示 |
| 频繁切换计费项目 | 切换记录 | 只能提示 |

> 风险事件是**待复核的线索，不是违规结论**。不得仅凭系统结果处罚成员或用于绩效评价。

### 3.9 工具中心

**工具中心** 列出 Saorsa 固定支持的 12 款工具：OpenCode、Claude Code、Codex CLI、Gemini CLI、Cline、Kilo Code、Qwen Code、TRAE、Qoder、JetBrains AI Assistant、GitHub Copilot、Cursor。每款工具显示：

- **已安装（Launcher 上报）**：成员本机的 Saorsa Launcher 检测到已安装；
- **网关可用**：已有经网关成功的请求；**用量已核实**：已有按供应商精确用量计费的请求；
- **部分托管 / 需官方账户**：哪些功能不经 Saorsa（例如 Cursor 的 Tab 补全、Copilot 的行内补全），以及是否还需要厂商账户；
- **实验室验证**：本仓库测试实际跑过的版本（mock 上游，非真实模型）。

“出现在列表中”不代表已经接入，请以这些状态为准。**Launcher 安装状态** 标签页列出每位成员每台设备上报的工具与版本。

在 **项目组详情 → 工具授权** 中勾选该项目组可以使用的工具；未授权的工具无法签发 Key，已签发的 Key 调用会被拒绝。在 **模型与密钥** 中可以为模型标注能力（工具调用、流式、图片、结构化输出）并限定允许的工具，网关会在调用前拒绝能力不满足的请求。

### 3.10 系统设置

- **企业策略**：组织名称、时区、成员/项目组的请求频率与 Token 上限、成员并发上限、数据保留天数、**最低 OpenCode 版本**（可选，低于该版本的客户端会被提示升级）、“受管客户端仅允许企业模型”开关，以及：
  - **Key 分配方式**：独占（先选先得，默认）或共享；独占时可设置空闲多少分钟自动释放（默认 30）。
  - **单设备登录**（默认开启）：同一账号在新设备登录后，旧设备自动退出。网页控制台和 OpenCode 分别计算——在 B 电脑登录网页会让 A 电脑的网页退出；在 B 电脑运行 `opencode auth login` 会让 A 电脑的 OpenCode 退出。在浏览器里授权 OpenCode 登录不会让网页退出。
- **员工使用告知**：修改后版本号自动 +1，成员下次连接 OpenCode 时需要重新确认。
- **检测规则**：开关各项规则、调整阈值（JSON 配置）。只有“敏感凭据泄露”可以设为“直接阻断”。若要启用审计模型判断项目相关性，必须设置 `allow_audit_model=true` 并指定一个已纳管的模型别名，同时先更新员工告知。
- **审计日志**：所有管理操作、登录、导出、查看风险详情等记录，不可修改或删除。
- **网关状态**：数据库、Redis、供应商健康、进行中请求、近 1 小时限流拒绝次数，以及 OpenCode 接入命令。

## 4. 成员指南

### 4.1 首次登录

1. 打开 Saorsa 网址，用管理员提供的账户和临时密码登录。
2. 系统会要求你设置新密码：至少 12 位，包含大写、小写、数字、符号中的三类，且不能包含用户名。
3. 修改密码后，你在其他设备上的登录（包括 OpenCode）会被注销，需要重新连接。

### 4.2 连接 OpenCode

Saorsa 支持**官方原版 OpenCode**，不需要安装任何定制版本。没装过的话先安装（任选一种）：

```bash
brew install opencode
```

```bash
npm install -g opencode-ai
```

然后在终端运行**一次**（把网址换成你们公司的 Saorsa 地址）：

```bash
opencode auth login https://saorsa.tech
```

终端会显示一个验证码，并自动打开浏览器授权页：

1. 如果还没登录，先登录 Saorsa；
2. 确认验证码与终端一致；
3. **选择本次连接的计费项目组**（费用只计入这一个项目组）；
4. 阅读使用告知，勾选“我已阅读并了解…”；
5. 点 **授权此客户端**。如果不是你本人发起的登录，点 **这不是我发起的**。

终端出现 `Logged into https://saorsa.tech` 即表示连接成功。之后进入任意项目目录，像平时一样打开 OpenCode 写代码：

```bash
cd 你的项目目录
opencode
```

模型列表里会出现：

- `saorsa/<模型名>`：OpenAI 兼容模型（默认选中第一个）
- `saorsa-anthropic/<模型名>`：Claude 等 Anthropic 协议模型

其他非企业模型会被隐藏。也可以一次性执行任务：

```bash
opencode run -m saorsa/deepseek-chat "解释一下这个项目的目录结构"
```

**模型、价格、授权和限制都由 Saorsa 在 OpenCode 每次启动时下发**：管理员新增或调整模型后，你只需要重新打开 OpenCode，不需要重新登录，也不需要更新任何配置。

> - macOS、Linux 的登录命令使用系统自带的 `sh` 和 `curl`；Windows 请在 PowerShell 中运行 `opencode auth login <Saorsa 地址>/windows`（末尾多一个 `/windows`），不需要 WSL 或 Git Bash。
> - 登录一次后长期有效（连续 30 天未使用才会过期）；修改密码、被强制下线或被移出项目组后需要重新登录。
> - 如果 OpenCode 里只剩下一个“请重新登录”的模型，说明登录已失效，再运行一次 `opencode auth login https://saorsa.tech` 即可（Windows 为 `https://saorsa.tech/windows`）。

### 4.2.1 更新 OpenCode

OpenCode 由你自己更新，Saorsa 不需要你做任何额外操作：

```bash
opencode upgrade
```

（或使用安装时对应的 `brew upgrade opencode` / `npm install -g opencode-ai@latest`。）管理员可能设置了**最低版本要求**，如果看到“OpenCode 版本过旧……请运行 opencode upgrade”，升级后重试即可。

### 4.2.2 选择 Key（模型）

管理员开启“Key 独占分配”时（默认），每个 Key 同一时间只给一个人用：

- 打开 **我的工作台 → 我的 Key**，下拉框中每一项是一个供应商（如 GLM、MiniMax、Kimi），括号里是**当前空闲的 Key 数**，为 0 时不能选择；你正在用的一项显示“使用中”。数字会随其他成员的选择实时变化。
- 也可以不在网页选择，直接在 OpenCode 中选模型开始对话：第一次调用会自动分配一个空闲 Key。
- 在 OpenCode 中换成其他供应商的模型时，如果那边有空闲 Key 会自动换过去，原来的 Key 释放给别人；如果那边没有空闲 Key，会提示哪些模型还有空闲，你原来的 Key 保持不变。
- 用完可以点 **释放**；连续 30 分钟（以管理员设置为准）没有调用、退出 OpenCode 登录时也会自动释放。
- 在 OpenCode 里问 AI“现在还有哪些模型有空闲 Key”，`saorsa_status` 工具会返回实时数量。

### 4.2.3 使用其他工具（工具中心与 Saorsa Launcher）

打开 **工具中心**，已授权的工具会显示“已授权”和连接方法。点卡片上的 **查看详细连接方式**，进入该工具的完整指南：选择计费项目组与模型、选择 macOS/Linux 或 Windows PowerShell，页面会把 Saorsa 地址、模型别名填进每一条命令和配置；需要 Key 的方式可以直接在页面上生成，生成后自动填入步骤（只显示一次）。每种连接方式都标明“已在实验室验证”或“依据官方文档、未验证”，并附有确认接通的方法与常见问题。命令行里也可以运行 `saorsa guide <工具>` 查看同样的步骤。

概要：

- **命令行工具**（Claude Code、Codex、Gemini CLI、Qwen Code、Copilot CLI）：先安装 Saorsa Launcher（每台电脑一次，`saorsa` 命令装好后才存在；不需要管理员权限，会自动校验 SHA-256 并加入 PATH）：
  ```powershell
  [Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor 3072; irm https://saorsa.tech/install.ps1 | iex   # Windows PowerShell（整行复制；开头一段启用 TLS 1.2）
  ```
  ```bash
  curl -fsSL https://saorsa.tech/install.sh | sh  # macOS 终端
  ```
  安装后（Windows 提示找不到 saorsa 时重新打开 PowerShell 窗口）：
  ```bash
  saorsa login --server https://saorsa.tech      # 浏览器中确认
  saorsa install claude-code                      # 从官方来源安装，会先询问
  saorsa launch claude-code --dir ~/my-project    # 启动；凭证只在这次启动的进程里
  ```
  Gemini CLI 第一次使用前运行 `saorsa configure gemini-cli`（会修改并备份 `~/.gemini/settings.json` 的一项认证设置，可用 `saorsa restore gemini-cli` 撤销）。
- **IDE 类工具**（Cline、Kilo Code、Cursor、TRAE、JetBrains AI Assistant、VS Code 中的 Copilot Chat）：在工具中心选择计费项目组，点 **生成 Saorsa Key**，按卡片上的字段填入工具设置。Key **只显示一次**，只能用于这个工具，可在“个人设置 → 登录设备”中撤销。不要发到聊天或提交到代码仓库。
- 遇到问题运行 `saorsa doctor`，它会检查服务器、登录、凭证与本机工具。

注意：部分工具的部分功能（补全、厂商自带模型、云端功能）不经过 Saorsa，卡片上会标明“部分托管”。

### 4.3 切换计费项目组

如果你属于多个项目组，有两种方法：

- **网页切换**：进入 **我的工作台**，在“OpenCode 客户端会话与当前计费项目”里为某个客户端选择新的项目组。下一次调用就会按新项目组计费，OpenCode 里的模型名称约 1 分钟后更新。
- **重新登录**：再次运行 `opencode auth login https://saorsa.tech` 并选择另一个项目组。

每次切换都会被记录。请按实际工作内容选择项目组。

### 4.4 查看自己的用量

- **网页**：**我的使用量** 显示你的费用、Token、按项目组的分布和每一次请求记录。你只能看到自己的数据。
- **OpenCode 里**：直接问 AI“我当前的计费项目和预算是多少”或“我最近 7 天的用量”，Saorsa 提供的 `saorsa_status`、`saorsa_usage` 工具会返回你的数据。
- **我的工作台**：顶部的 **我连接的工具** 列出你连接过的每一款工具（有 OpenCode 登录或工具 Key、经 Launcher 启动过、Launcher 上报已安装、或周期内有请求），每款显示：连接方式与计费项目组（可撤销）、Launcher 上报的设备与版本、请求数、成功率、费用（标注估算次数）、输入/输出/缓存 Token、平均耗时、最近使用时间、用过的模型以及每日趋势，可切换近 7 / 30 / 90 天；点“查看请求明细”会打开按该工具筛选的 **我的使用量**。下方还显示你所属的项目组、可用模型和个人预算。
- **我的使用量**：可按工具筛选，并有“按工具”汇总表。

### 4.5 通知、风险提示与申诉

- 右上角铃铛和 **我的通知** 会显示额度提醒、风险提示和复核结果。
- **我的使用量 → 风险提示** 列出与你相关的风险记录。风险提示需要管理员人工复核，**不代表违规认定**。
- 如有异议，点 **申诉** 说明情况，管理员复核后你会收到通知。

### 4.6 账户安全

- **个人设置** 可以修改密码、查看和注销你的登录设备（网页和 OpenCode 客户端）。
- 管理员开启“单设备登录”时（默认），同一账号同时只能在一台设备上登录网页、一台设备上使用 OpenCode。在新设备登录后，旧设备会自动退出并提示“账号已在其他设备登录”；如果不是你本人操作，请立即修改密码。
- 不要在对话中粘贴密钥、私钥、密码等敏感信息；系统检测到后会记录脱敏的风险事件，管理员也可能设置为直接拦截。

## 5. 常见提示与处理办法

| OpenCode 或网页中的提示 | 原因 | 怎么办 |
|---|---|---|
| `… budget exhausted …` / 预算耗尽 | 个人、项目组或企业预算已用完 | 联系管理员提高额度或临时提额；OpenCode 不会自动重试 |
| `This request could cost up to …` | 单次请求超过预算设定的单次上限 | 缩小上下文或降低最大输出 |
| `Rate limit reached …` | 达到每分钟请求数或 Token 上限 | 无需操作，OpenCode 会按提示的时间自动等待并重试 |
| `Too many concurrent requests …` | 达到并发上限（个人、项目组、模型或供应商） | 等待正在进行的请求结束，OpenCode 会自动重试 |
| `This request (~… input tokens) is larger than … token rate` | 单个请求就超过了每分钟 Token 上限 | 缩小上下文，或请管理员提高上限 |
| `not authorized for your current billing project` | 该模型没有授权给当前项目组 | 换用已授权的模型，或请管理员授权 |
| `no longer a member of the selected billing project` | 你已被移出当前计费项目组 | 切换到其他项目组或重新登录 |
| `Saorsa 登录已失效或被撤销` / 模型列表只剩“请重新登录” | 密码已修改、被强制下线、被移出项目组或长期未使用 | 重新运行 `opencode auth login https://saorsa.tech` |
| `OpenCode … 版本过旧` | 低于管理员设置的最低版本 | 运行 `opencode upgrade` |
| `… 的 n 个 Key 都在被其他成员使用` | Key 独占分配下，该供应商的 Key 已全部被占用 | 按提示切换到还有空闲 Key 的模型，或稍后再试 |
| `账号已在其他设备登录` / 模型列表只剩“请重新登录（账号已在其他设备登录）” | 单设备登录：你在另一台设备登录了 | 如需在本机继续使用，重新运行 `opencode auth login https://saorsa.tech`（另一台设备会退出） |
| `Blocked by organization policy …` | 请求中包含疑似密钥等敏感信息，且管理员开启了阻断 | 删除敏感信息后重试 |
| 上下文过长（context length） | 对话超过模型上下文 | OpenCode 会自动压缩上下文；也可开始新会话 |
| `upstream provider … rate limiting` / `temporarily unavailable` | 上游供应商限流或故障 | 会自动重试；持续出现请联系管理员 |
| `provider account has no remaining quota` | 公司在供应商处的余额用完 | 联系管理员充值或更换 Key |

## 6. 隐私与审计说明

- **采集范围**：只记录经企业网关的受管调用：时间、成员、计费项目组、模型、Token、费用、状态码。不采集个人账户、私人仓库、终端或设备上的其他活动。
- **不保存对话全文**：只有安全规则命中时才保存脱敏片段和哈希指纹。
- **谁能看**：管理员可以看统计数据和脱敏的风险证据，每次查看风险详情都会记录；成员只能看自己的数据。
- **保留期**：请求明细中的个人标识信息默认 180 天后清除，风险证据默认 365 天后清除（管理员可调整）。
- **申诉**：任何风险记录都可以申诉。
- **覆盖边界**：Saorsa 只能统计经过网关的调用。使用未纳管的工具或个人 Key 的调用不在统计范围内；企业如需强制管控，应配合网络出口策略和终端管理（见 `deployment.md` 第 5 节）。

## 7. 常见问题

**Q：成员能看到公司的 API Key 吗？**
不能。Key 只保存在服务端并加密，OpenCode 拿到的是短期有效的个人令牌，只能访问企业网关。

**Q：为什么界面上的费用和供应商账单有一点差别？**
标记“估算”的请求是按内容长度估算的；供应商账单还可能有四舍五入或折扣。管理员可以在请求详情里做对账调整。

**Q：我同时在两个项目组，费用会算两次吗？**
不会。每次调用只计入当时的计费项目组。

**Q：断网或中途取消会被重复计费吗？**
不会。每次请求只结算一次；中途取消的请求按已产生的内容估算计费。

**Q：AI 判断我“与项目无关”，会被处罚吗？**
不会自动处罚。这只是给管理员的复核线索，必须人工核实；你也可以申诉。

**Q：忘记密码怎么办？**
请管理员在“成员管理 → 成员详情 → 重置密码”为你生成新的临时密码。

**Q：管理端升级后，成员需要更新客户端吗？**
不需要。成员使用官方 OpenCode 并自行升级；模型、价格、授权、限制和用量工具都由 Saorsa 在 OpenCode 启动时下发，Saorsa 升级后成员重新打开 OpenCode 即可生效。

**Q：之前用 TeamOS / NexCode 登录过，现在怎么办？**
平台已更名为 Saorsa，模型显示为 `saorsa/…`、`saorsa-anthropic/…`。NexCode 时期登录的无需操作；如果模型列表只剩“请重新登录”，重新运行一次 `opencode auth login <你们的 Saorsa 地址>` 即可。若你在自己的 `opencode.json` 中写死了 `teamos/…` 或 `nexcode/…` 模型名，请改成 `saorsa/…`。

**Q：本地演示环境的测试账号在哪里？**
运行 `scripts/dev-setup.ts` 创建的演示账号（`admin`、`alice`、`bob`、`carol`），密码随机生成并保存在 `.data/dev-credentials.json`。仅用于本机开发，不要用于生产。
